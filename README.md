# auc_finder — мото-аукцион-бот на платном фиде aleado

Бот отслеживает мотоциклетные лоты на японских аукционах и присылает
подходящие под ваши фильтры (марка/модель/годы/цена) прямо в Telegram —
с фото и оценкой состояния, если они есть в данных. Кнопки отвечают
мгновенно (это постоянно работающий процесс, не задача по расписанию).

## Как это устроено

- **Источник данных** — платный фид aleado (логин `jmmoto_user`): на FTP
  лежит BZip2-архив с готовым MySQL-дампом (таблица `moto_lots_ns`).
  `aleado_client.py` скачивает архив, распаковывает, импортирует дамп в
  MySQL и оттуда читает лоты — подробности и почему именно так, а не
  свой разбор SQL-текста, см. в комментариях в начале `aleado_client.py`.
  Прежние источники (bid.cars — США Copart/IAAI за Cloudflare, и прямой
  разбор jmmoto.ru) убраны полностью.
- **Состояние бота** (список фильтров/подписок и уже отправленные лоты,
  `db.py`) — тоже в MySQL, не в JSON-файлах на диске: контейнерный
  хостинг вроде Railway пересоздаёт файловую систему при каждом
  редеплое, файлы бы обнулялись, база — нет.
- **Хостинг** — Railway: деплоит прямо из этого GitHub-репозитория по
  `Dockerfile`, держит процесс живым 24/7, и там же поднимается MySQL
  (отдельный плагин в том же проекте Railway) — никакого своего сервера
  и возни с yum/systemd/CentOS.

## Файлы в репозитории

```
bot_server.py     — сам бот (Telegram: кнопки, фильтры, рассылка)
aleado_client.py  — скачивание/разбор фида aleado (FTP + BZip2 + MySQL)
db.py             — состояние бота в MySQL (подписки, уже отправленные лоты)
debug_aleado.py   — диагностика подключения к фиду, шаг за шагом
Dockerfile        — образ для Railway (Python 3.11 + клиент mysql)
railway.json      — настройки деплоя Railway (сборка по Dockerfile)
requirements.txt  — зависимости Python
.env.example      — какие переменные окружения нужны (для локального запуска)
.gitignore        — .env и подобное сюда не попадает
```

## Деплой на Railway

### 1. Создайте проект в Railway из этого репозитория

В Railway: New Project → Deploy from GitHub repo → выберите
`sidru666-dot/auc_finder`. Railway увидит `Dockerfile`/`railway.json` и
соберёт образ сам.

### 2. Добавьте MySQL

В том же проекте: New → Database → Add MySQL. Railway сам создаст базу
и пропишет сервису переменные `MYSQLHOST`, `MYSQLPORT`, `MYSQLUSER`,
`MYSQLPASSWORD`, `MYSQLDATABASE` — `db.py` и `aleado_client.py` уже
умеют их читать (без подчёркивания, ровно как называет их Railway), в
`.env` руками их дублировать не нужно.

### 3. Переменные окружения сервиса бота

В настройках сервиса (Variables) добавьте:

```
TELEGRAM_BOT_TOKEN=...          # токен от @BotFather

ALEADO_FTP_HOST=auctionsdata.aleado.com   # см. раздел ниже про адрес
ALEADO_FTP_PORT=21
ALEADO_FTP_USER=jmmoto_user
ALEADO_FTP_PASSWORD=co6AepeiAegh5ku9
```

Остальное (`ALEADO_FTP_DIR`, `ALEADO_FTP_FILENAME`, `ALEADO_TABLES`,
`ALEADO_REFRESH_TTL_SECONDS`, `CHECK_INTERVAL_SECONDS`) — необязательно,
у всего есть разумные значения по умолчанию (см. `.env.example` — там
же и объяснение каждой). `MYSQL_*` можно не трогать вообще: Railway их
подставит сам через переменные `MYSQL*` из плагина базы (см. шаг 2).

### 4. Деплой и проверка

Railway задеплоит автоматически после первого пуша/подключения
репозитория, и дальше — при каждом новом коммите в `main`. Смотрите
логи сервиса в Railway (вкладка Deployments → Logs):

- `Схема БД готова (...)` — подключение к MySQL и создание таблиц
  бота прошло успешно;
- `Бот запущен, проверка каждые ... сек.` — можно идти в Telegram и
  писать `/start`.

Если что-то не так с фидом aleado (не тот хост, не те колонки и т.п.) —
это не мешает боту запуститься и отвечать на команды, только лоты не
будут приходить, пока не поправите (см. следующий раздел).

## Адрес FTP-сервера aleado

Исходные реквизиты были такие, но с опечаткой:

```
host: auctiondata.aleado.com    <- без "s", НЕ резолвится в DNS (домена нет)
port: 21
username: jmmoto_user
password: co6AepeiAegh5ku9
```

Правильный хост, судя по всему — **`auctionsdata.aleado.com`** (с «s»,
auctions+data): в отличие от исходного и всех остальных проверенных
вариантов, этот проходит DNS. Уже прописан в `.env.example` и в шаге 3
выше. Если после деплоя в логах Railway видно, что FTP всё равно не
подключается — уточните у поставщика точный адрес (и заодно: нужно ли
слать им статический IP Railway для белого списка — у Railway он не
фиксированный по умолчанию, это отдельная настройка, если понадобится).

Дополнительно, не блокирует запуск, но полезно уточнить у поставщика
при случае:
1. Точное имя файла архива на FTP (если не всегда одинаковое — бот сам
   найдёт самый свежий `*.bz2` в указанной папке, но лучше знать точно).
2. Как часто обновляется дамп (влияет только на `ALEADO_REFRESH_TTL_SECONDS`).
3. Если в тарифе, помимо мотоциклов (`moto_lots_ns`), заявлены другие
   типы техники — названия соответствующих таблиц, чтобы дописать в
   `ALEADO_TABLES`.

## Формат фида (со слов поставщика)

Не CSV и не XML — **BZip2-архив с готовым MySQL SQL-дампом**. После
распаковки — обычный `.sql`-файл с `CREATE TABLE` + `INSERT INTO`.
Таблица `moto_lots_ns` (мотоциклы), поля: ID лота, дата, номер лота,
аукцион, марка, модель, год, тип кузова/рамы, пробег, объём двигателя,
начальная и конечная цена, цвет, оценки узлов, результат торгов, VIN,
ссылки на фотографии, описания на английском/русском.

Точные технические имена колонок в дампе мы не знаем заранее (поставщик
описал их по-человечески, не как названия полей в базе) — поэтому
`aleado_client.py` не завязан на конкретные имена: после импорта дампа
он смотрит реальный список колонок (`DESCRIBE moto_lots_ns`) и сам
сопоставляет их с нужными полями бота (марка, модель, цена и т.д.) по
списку вероятных названий (`FIELD_CANDIDATES` в начале `aleado_client.py`).
Если что-то не сопоставится — `debug_aleado.py` это явно покажет.

## Локальный запуск (для разработки/отладки)

Нужен Python 3.9+ и доступ к MySQL/MariaDB (локально через Docker,
`docker run -e MYSQL_ROOT_PASSWORD=x -p 3306:3306 mysql:8`, или любой
другой):

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env    # заполните реальными значениями
export $(grep -v '^#' .env | xargs)

python3 debug_aleado.py   # проверка фида: FTP → BZip2 → импорт → колонки
python3 bot_server.py     # сам бот
```

## Как пользоваться ботом

- `/start` или `/help` — приветствие и главное меню с кнопками.
- **"➕ Добавить фильтр"** (или `/watch`) — по очереди кнопками выбираете
  марку → модель → год от → год до → максимальную цену → дальше
  необязательный экран "Доп. фильтры" (как на форме поиска jmmoto.ru):
  пробег, объём двигателя, оценка состояния, номер лота, VIN, свободный
  текст по описанию — можно заполнить сколько нужно или сразу нажать
  "Готово, к сохранению" → и в конце решаете: сохранить подписку и/или
  сразу посмотреть, что подходит прямо сейчас (результаты показываются
  порциями по 10 лотов с фото, дальше — кнопка "Показать ещё"/"Прекратить
  показ", а не всё одним потоком сообщений).
- **"📋 Мои фильтры"** (или `/mywatches`) — список ваших фильтров, у
  каждого две кнопки: "🔍 Проверить" (мгновенно) и "❌ Удалить".
- `/cancel` — отменить текущую настройку фильтра.

Список моделей под маркой — реальные названия из текущих лотов фида
aleado. Годы — кнопками или вручную ("2015" или просто "15"). Цена — в
рублях: порог задаётся в рублях, а в уведомлении о лоте цена
показывается и в йенах (как в исходных данных), и пересчитанная в
рубли по актуальному курсу ЦБ РФ на момент показа (курс обновляется
сам, раз в `CBR_RATE_TTL_SECONDS`, по умолчанию раз в 6 часов).

В уведомлении о лоте, если эти данные есть в фиде, дополнительно
показываются: оценка состояния (общая и по отдельным узлам), пробег,
объём двигателя, цвет, тип кузова/рамы, аукцион и дата торгов, номер
лота, VIN, результат торгов, и фото лота.

## Как самому запустить/остановить бота (без ожидания меня)

У Railway нет отдельной кнопки "Стоп" для такого сервиса (это не
serverless-функция, а постоянно работающий процесс) — но есть простой и
надёжный способ управлять им самостоятельно через сам сайт Railway,
без консоли и без ожидания, пока я это сделаю:

1. Зайдите на **railway.app** → откройте проект **auc_finder** → сервис
   бота (тот, что с `bot_server.py`, НЕ сервис MySQL).
2. Слева откройте вкладку **Variables**.
3. Найдите переменную **`TELEGRAM_BOT_TOKEN`**.
   - **Чтобы ОСТАНОВИТЬ бота** — нажмите на неё, сотрите значение
     (оставьте поле пустым) и сохраните. Railway сам передеплоит сервис;
     через 20–40 секунд процесс перестанет отвечать в Telegram (он
     специально написан так, чтобы сразу останавливаться без токена —
     это ожидаемо, ничего не сломается, база данных и все ваши фильтры
     никуда не денутся).
   - **Чтобы ЗАПУСТИТЬ бота обратно** — впишите в то же поле реальный
     токен и сохраните. Токен можно в любой момент заново посмотреть у
     **@BotFather** в Telegram: `/mybots` → выбрать бота → **API
     Token**. Через 20–40 секунд бот снова заработает.
4. Проверить, что сейчас происходит — вкладка **Deployments**: статус
   `SUCCESS`/`ACTIVE` = бот работает, `CRASHED` = остановлен (это
   нормально для способа выше), `DEPLOYING` = ещё применяет изменения,
   подождите немного и обновите страницу.

Там же, во вкладке Deployments, у последнего деплоя есть кнопка
**Redeploy** — она пересоздаёт процесс с текущими настройками (полезно,
если бот "завис" сам по себе, без изменения токена).

## Если что-то не работает

- Бот не отвечает вообще → логи сервиса в Railway (Deployments → Logs)
  — чаще всего неверный `TELEGRAM_BOT_TOKEN` или сборка не прошла.
- Ошибка `Conflict: terminated by other getUpdates request` в логах →
  где-то ещё работает второй процесс с тем же токеном (например, старый
  бот на прежнем сервере ещё не остановлен — остановите его, одновременно
  двух экземпляров с одним токеном быть не должно).
- Лотов долго нет / фид не обновляется → смотрите логи на предмет
  `aleado: обновление фида не удалось`; для пошаговой диагностики можно
  временно запустить `python3 debug_aleado.py` локально (см. раздел
  «Локальный запуск» выше) с теми же переменными окружения, что и на
  Railway.
- Уведомления приходят, но без каких-то полей (например, без оценки
  состояния) → в реальном дампе колонка называется не так, как
  предположено в `FIELD_CANDIDATES` (`aleado_client.py`) — `debug_aleado.py`
  покажет, какие канонические поля не нашли соответствия, и полный
  список реальных колонок — допишите нужное имя в список кандидатов
  одной строкой.
